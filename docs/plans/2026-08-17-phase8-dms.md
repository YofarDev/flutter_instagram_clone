# Phase 8 — Direct Messages Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: implement this plan task-by-task via subagent-driven-development.

**Goal:** 1:1 real-time chat: conversations list (from feed appbar paper-plane icon), chat screen with live messages + send, new-chat user picker reusing username search.

**Architecture:** New `chat` feature. **Deterministic conversation ids**: `conversations/{uidA_uidB}` with uids sorted — getOrCreate needs no queries. Conversation doc denormalizes participant meta + lastMessage; messages in subcollection. Two cubits: `ConversationsCubit` (live list), `ChatCubit` (live messages + send). New-chat picker = `IExploreRepository.searchUsers` (cross-feature public-contract import — sanctioned pattern).

**Key decisions (ponytail):**

- **1:1 only, deterministic id** — group chats would need generated ids + participant queries; deferred.
- **Send = one batch**: message doc add + conversation doc update (lastMessage, updatedAt). `// ponytail: fixed 1:1 shape; groups later`.
- **Participant meta snapshot** on conversation create (username/avatar denormalized — stale after profile edits, same ceiling as follow edges).
- **No typing indicators / read receipts / push** — deferred.
- **Rules**: participants-only read/write; conversation update allowed by participants when only lastMessage/updatedAt touched (field-scoped, mirrors posts counts pattern); messages: create by sender.
- **Unread counts**: deferred (no per-user lastRead tracking — badge infra exists in Phase 6 if wanted later).

### Task 2: ChatRepositoryImpl (TDD) + rules deploy

House pattern. ~8 tests (watch pass-throughs ×2, getOrCreate success/failure, sendMessage success/failure + param forwarding).
Rules block:

```
match /conversations/{convId} {
  allow read: if signedIn() && request.auth.uid in resource.data.participants;
  allow create: if signedIn() && request.auth.uid in request.resource.data.participants;
  // participants may only bump lastMessage/updatedAt
  allow update: if signedIn() && request.auth.uid in resource.data.participants
      && request.resource.data.diff(resource.data).affectedKeys()
          .hasOnly(['lastMessage', 'updatedAt']);
  allow delete: if false;

  match /messages/{mid} {
    allow read: if signedIn() && request.auth.uid in
        get(/databases/$(database)/documents/conversations/$(convId)).data.participants;
    allow create: if signedIn() && request.resource.data.senderId == request.auth.uid
        && request.auth.uid in
        get(/databases/$(database)/documents/conversations/$(convId)).data.participants;
    allow update, delete: if false;
  }
}
```

NOTE: messages rules use `get()` on parent conversation — 1 extra read per rules evaluation per op; acceptable. VERIFY the update-rule interplay with sendMessage's BATCH: update evaluates against PRE-batch state (Phase 3 lesson!) — conversation doc exists pre-batch with participants ✓ (only lastMessage/updatedAt touched ✓) — batch is safe.
